# ember — case study artifacts

Everything here is produced by a script or written alongside the work, never
retrofitted. One command runs all of it:

```bash
npm run verify
```

It builds, starts a production server, runs every measurement against it and
stops it again. That last part is the point: the scripts used to take a base
URL and trust whatever answered, and phase 17 opened by reading seven
accessibility violations that were a two-day-old `next start` rather than the
code ([ADR 0028](../decisions/0028-the-gate-owns-the-server.md)). Individual
steps still work — `npm run verify -- --only=audit` — and every step exits
non-zero on a failure, so the whole thing is a gate rather than a report nobody
reads.

Never `next dev`: the dev overlay injects its own DOM, the service worker is
deliberately not registered in development, and React's development build
renders extra attributes. Measuring any of that measures the harness.

## Measured, not claimed

All figures below are the current output of `npm run verify`. **The route counts
in the table above had been stale since phase 23** — they said 52 audits and 54
captures against an actual 68 and 66 — which is the failure this document exists
to prevent, sitting inside the document itself. They are regenerated by hand from
the gate's own output now, and the day that stops happening is the day this table
should be generated rather than written. **The v1 numbers this table used to carry are gone rather than
archived** — the palette, the typeface, the layout, the universe and the engine
predicate all changed, which is five independent reasons the old figures
described nothing that still exists.

**Accessibility: 0 violations** across 17 screens × 2 themes × 2 widths, at
WCAG 2.1 AA plus axe's best-practice rules. It started at 62 — see
[ADR 0018](../decisions/0018-colours-are-calibrated-against-their-own-tints.md).
Since phase 15 the audit seeds a real book with two positions driven through
their stops, so the risk rows and the tinted severity badge are actually
measured rather than never rendered.

**Lighthouse**, cold, with the first-run cookie set so the figures describe the
app rather than the redirect to setup:

| | Desktop | Mobile |
|---|---|---|
| Performance | 99–100 | 68–83 |
| Accessibility | 100 | 100 |
| Best practices | 100 | 100 |
| SEO | 100 | 100 |
| LCP | 0.8–0.9 s | 4.5–6.6 s |
| TBT | 0 ms | 63–124 ms |

Mobile is the throttled profile — simulated slow 4G with a 4× CPU penalty.
There is no image to blame: the critical path is the stylesheet and the app's
own JavaScript, and mobile is where a 214-instrument universe costs something.
The signals feed is the floor at 68: it renders the largest payload, and that
payload grew a third when the ensemble went from ten rules to sixteen.

**Layout shift**, observed with a `PerformanceObserver` on a seeded ledger,
because the shift left in this app is markup that only exists when there *is* a
book:

| | Mobile | Desktop |
|---|---|---|
| Twelve of fourteen measured screens | < 0.025 | < 0.025 |
| Asset detail | 0.067 | 0.025 |
| Settings — account | 0.065 | 0.017 |

The asset page's share is one honest thing:
`Your position` is inserted the moment `localStorage` becomes readable, because
the server cannot know there is a book. Closing it needs a cookie mirroring the
ledger's existence — the [ADR 0014](../decisions/0014-onboarding-gate-is-a-cookie-read-at-the-edge.md)
pattern — which is a decision to take deliberately rather than to reach for
because a number is ugly. See [ADR 0019](../decisions/0019-skeletons-are-sized-by-type-metrics.md).

The settings figure is newer and **not yet diagnosed**, which is the honest state
to publish it in. The suspect is the risk-comparison skeleton: its row headers
reserve space using placeholder words rather than the real labels, so they may
wrap to fewer lines than the settled table does — ADR 0019's own mechanism
defeated by using stand-in strings. It needs measuring in a browser, not
reasoning about, which is the whole point of this document.

**No horizontal overflow** at any of 320 / 375 / 414 / 640 / 768 / 1024 / 1280
/ 1440 / 1920px, on any of the sixteen routes.

**Tests:** 356, covering the indicator maths, the exposure triggers, finding
ranking, backtest invariants, portfolio arithmetic, CSV round-tripping, alert
scheduling for both kinds of finding, the news/engine boundary, and four guards
that fail on drift rather than on breakage — if the type scale diverges between
`globals.css` and `cn()`; if anything under `lib/signals` imports a news
module; if an instrument is added without the symbol mapping a live provider
needs; and if the live provider is selected without the flag and both keys.
A fifth now fails if a field is added to `Instrument` and not carried through
`toInstrument` — the check that exists because three hand-written copies of that
literal silently dropped `exchange`, leaving every equity on earth with an
execution window computed in New York hours. A sixth measures the correlation
between every pair of strategy scores across the whole equity universe and fails
if two rules have become the same rule — it caught one on its first run.

**One rule decided an architecture.** The service-role key must never appear
under `src/` — it is the one credential that can ignore row-level security, and
nothing the application does needs it. Phase 26 had to send push notifications and
email digests, which means reading every recipient's watchlist, which RLS
correctly forbids to the public key. The obvious answer is an API route behind a
shared secret; that answer just moves the forbidden credential into `src/` and
puts a password in front of it. So both senders are **scripts a scheduler runs**,
and possession of the key is the authentication. Unsubscribe had the same problem
from the other end — it must work for someone with no session — and it is solved
the same way: a `security definer` function in Postgres that can flip one boolean
on one row and do nothing else, granted to anonymous callers, rather than a route
holding a key that could do anything.
See [ADR 0037](../decisions/0037-the-server-reaches-you-and-the-key-stays-out.md).

**Nothing third-party reaches the browser, and it is checked rather than
promised.** Every remote origin in the built client bundle is Supabase or a
documentation link Next.js compiles in. No ad network, no analytics, no tag
manager, no pixel — and no API key, no service-role key and no engine internals
either. ember's own sponsor slot is four fields from a Postgres row rendered in its
own typography, which is what makes "we don't track you" a checkable claim instead
of a value.

**The provider seam held.** Phase 1 built the engine against generated data on
the explicit promise that turning on real data would be an env var and a second
implementation. Phase 21 connected four live upstreams — Yahoo, Finnhub,
CoinGecko and the ECB — **without touching a component, a route, a store or an
engine module.** The one thing that did change was a paragraph on the
methodology page asserting "prices in this build are generated", which had been
true for five phases and became a lie the moment a feed was connected; it reads
the provider now. See [ADR 0033](../decisions/0033-live-data-is-four-providers-and-one-of-them-is-a-problem.md).

## Eleven things measurement found that reading would not have

Worth reading as a set, because they are one failure in five costumes: a rule
that was written down, believed, and never checked.

1. **The type scale wasn't applying.** tailwind-merge assumes an unfamiliar
   `text-*` is a colour, so `text-micro` was being deleted by the `text-stone`
   beside it — in 27 components across every phase.
   ([ADR 0016](../decisions/0016-cn-is-taught-the-type-scale.md))
2. **The risk profile didn't change anything.** All three profiles surfaced
   identical calls, because a confidence floor shared by all of them was doing
   the filtering while the per-profile threshold never bit.
   ([ADR 0013](../decisions/0013-risk-profiles-move-both-halves-of-the-bar.md))
3. **A jump fed its own volatility.** Every price shock ratcheted the GARCH
   variance permanently upward until it overflowed and the whole series went
   `NaN`. Thirteen instruments never rolled it; 110 did.
   ([ADR 0026](../decisions/0026-the-jump-fed-the-variance.md))
4. **The audit script's comment was a lie.** It claimed to seed a sample book
   and only seeded preferences, so every portfolio screen had been audited
   empty since the day it was written.
5. **The gate was reading a stale server.** Seven violations, four of them the
   Next.js error page, none of them real.
   ([ADR 0028](../decisions/0028-the-gate-owns-the-server.md))
6. **The API's documentation disagreed with the API.** Every Finnhub endpoint
   was probed against the real key before a line of the live provider was
   written, and the free tier turned out to serve no price history at all —
   `/stock/candle`, `/crypto/candle` and `/forex/candle` are all 403. That
   single fact decided the whole architecture. Two more of the same kind
   followed once data was flowing: CoinGecko returns an absolute change and a
   percentage change computed from different snapshots, which disagreed in
   sign; and matching headlines on the first word of a company name turned
   `Bank of America` into `\bBank\b`, putting "bank" top of the trending strip
   attributed to Intel and BlackRock.
   ([ADR 0033](../decisions/0033-live-data-is-four-providers-and-one-of-them-is-a-problem.md))

7. **Two of the ten strategies were one strategy.** Dual momentum's score was
   the same expression, character for character, as time-series momentum's — the
   two correlated at exactly **1.00** across 176 equities. The engine cannot
   notice this on its own: it weights each rule by its confidence and *raises*
   blended confidence when rules agree, so a duplicated opinion does not cancel
   out, it manufactures the unanimity this product exists to avoid faking.
   ([ADR 0035](../decisions/0035-six-more-rules-and-the-three-defects-they-exposed.md))
8. **The most expensive thing in the engine was a loop that should not have
   existed.** Profiled, `clenow` cost 1,726ms against 257ms for every other rule
   put together — essentially the whole cost of the track record. It converted
   420 bars of every peer to produce ninety numbers, which is the exact mistake a
   comment three files away warns about, and it recomputed a market-wide quantity
   once per subject. Moving it into a per-date snapshot took the walk-forward from
   50.7s to 24.9s with byte-identical output.
   ([ADR 0035](../decisions/0035-six-more-rules-and-the-three-defects-they-exposed.md))

9. **Two window levers were built and turned out to be inert.** Narrowing the
   execution window when the rules disagree is the right idea, and the elegant
   implementation — shorten the signal's effective half-life — moved no window's
   boundary by a single hour. Decay across a 72-hour horizon varies between 0.92 and
   0.96 for every call this engine makes, against a liquidity term that swings from
   nothing to one inside a session. Dissent had to move to the threshold that
   decides the span instead, where it takes an equity window from six hours to one.
   ([ADR 0036](../decisions/0036-the-window-engine-and-two-inert-levers.md))
10. **A planned feature was built, measured, and removed.** A risk-profile axis
   excluding short-horizon trades from a conservative book filtered nothing —
   17→17, 78→78, 143→143 — because a fast rule cannot lead a call in a sixteen-rule
   blend when its own confidence is capped. Mean-reversion led 6 of 143 calls on the
   most aggressive profile and none at all on the other two. Shipping it inert would
   have put a claim in the settings table the product does not keep.
   ([ADR 0036](../decisions/0036-the-window-engine-and-two-inert-levers.md))

11. **A screen that had been "done" for a phase had never been checked.** The
   accessibility audit walks a hand-written route list, and `/unsubscribe` shipped
   outside it — so nothing had ever loaded it. The first audit that included the
   route reported **twelve violations**, then four after the first fix, before
   passing. Both defects were real and neither was visible in review: the screen
   rendered its own `<main>` inside the app shell's, giving the page two `main`
   landmarks; and the layout's "skip to content" link targets `#main`, which this
   screen's `<main>` did not have — so the skip link pointed at nothing, which is
   also why axe stopped exempting it. The rule that came out of it is that a new
   screen joins both scripts in the same commit.

Items 2 and 7 are worth reading together, because the first recurred. Adding six
rules in phase 24 shifted the confidence distribution down — `assess()` penalises
both disagreement and abstention, and both grow with the number of rules whether
or not the new rules are informative — so the floors calibrated in ADR 0013 quietly
became the only filter again, and the Conservative profile fell to four
instruments out of 214. A relative scale with fixed thresholds on it will keep
doing that.

Item 5 is the one that matters most, because it is about the instrument rather
than the thing being measured. It is also what turned the other measurements
into a single command, and running that command end to end immediately found
four layout defects that had been shipping for two phases.
